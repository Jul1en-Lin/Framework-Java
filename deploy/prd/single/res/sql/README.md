# 私有初始化输入

本目录的 `*.sql` 被 Git 忽略。公开 checkout 不包含可直接用于生产的凭据、账号或业务数据，首次部署前必须从受控渠道准备：

| 文件 | 内容 |
|---|---|
| `nacos-auth.sql` | 明确选择 `frameworkjava_nacos_prd`，向 `users`、`roles` 写入目标环境账号、bcrypt 密码哈希及所需角色 |
| `nacosdata.sql` | `frameworkjava-prd` 命名空间及服务/共享配置，包含目标中间件连接和第三方服务凭据 |
| `db.sql` | 经批准的业务表结构与初始数据，导入目标为 `frameworkjava_prd` |

现有本地导出仅作为私有输入保留，不是通用生产种子。`nacos-auth.sql` 中账号对应的明文密码应与私有 `.env` 的客户端登录配置一致；不得保存明文密码到 SQL。需要生成新 bcrypt 哈希时，可以使用 `htpasswd -nBC 12 <username>` 交互输入密码，将输出的哈希部分交由初始化 SQL 使用；输出和 SQL 都按秘密管理，不粘贴到 issue、日志或聊天。不要用命令行参数传入密码。SQL 中用户名等文本必须正确转义并经过审核。

导出文件可能包含 DROP、DELETE、账号哈希和用户数据。仅在首次空环境初始化时使用整套文件；不得为修复现有 Nacos 的读取问题而重导。文件传输使用 SSH，限制本地和服务器访问权限；容器初始化用户需要对挂载文件有读取权限。

保持凭据只存在于私有运行环境和配置中心；不要将私有 SQL 打入业务 JAR 或 Docker 构建上下文，不要强制加入 Git。
